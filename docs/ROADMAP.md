# Roadmap to Trailgate v1.0.0

Updated: 2026-10-25. This is a release roadmap for **Trailgate the library and CLI**. It does not depend on training a retrieval model or publishing any real trajectory data. Versions below describe capability milestones. A local commit, GitHub push, version tag, and package release are separate actions; the package version alone does not imply a published release.

## Product contract for v1.0.0

Trailgate prepares trajectories from a user's own Langfuse project. It obtains or imports a bounded source snapshot, preserves source evidence, reconstructs the observable agent run, and explains which decisions can be exported to a specified training view. A useful result is a **reproducible eligibility decision with reasons**, not a JSON conversion alone.

For v1, the supported source is Langfuse. The read contract is [Observations API v2 and Scores API v3](https://langfuse.com/docs/api-and-data-platform/features/public-api), plus complete [enriched blob export manifests](https://langfuse.com/docs/api-and-data-platform/features/export-to-blob-storage) for bulk intake. Langfuse distinguishes [observations, traces, and sessions](https://langfuse.com/docs/observability/data-model); Trailgate must not silently equate any one of those with a complete episode. Server and SDK versions supported in practice will be listed in a tested compatibility matrix. In particular, Langfuse Python SDK v4 and v5 use different score-read accessors, so the collector must keep that difference inside its adapter or use the stable REST endpoints.

The v1 outputs are (1) an immutable local source snapshot, (2) a versioned episode/decision/action/observation view with source references, (3) an audit report separating structural fidelity, quality signals, rights, and missing evidence, and (4) opt-in generic episode and **supported-format** SFT exports. A Langfuse score is an attributed signal, not proof that every action was correct. A provider-native Responses capture is not automatically a Chat SFT example.

The core package does not run models, fine-tune them, judge answer quality, or send datasets to a training provider. It does not claim that a trace alone contains exact model-visible context. Direct Codex/Claude Code log ingestion, multi-source connectors, preference/RL-ready export, and automated legal clearance are outside v1.

## Milestones

| Milestone | Deliverable | Exit gate |
|---|---|---|
| **v0.1.0 — honest public preview** | Provide the offline snapshot importer, capture helper, decision audit, and synthetic fixture. Document the exact CLI commands, supported input shape, known exclusions, and private-by-default behavior. Keep opt-in model examples separate. | A fresh checkout can install, test, run the fixture, and build an sdist/wheel. Candidate artifacts and the Git tree contain no `.env`, private archive, dataset text, or credential. README does not imply episode stitching or online pulling exists. |
| **v0.2.0 — canonical episode graph** | Introduce versioned IDs and links for episode, decision, action, delivered observation, trace/session, and score subject. Preserve raw event order separately from reconstructed causal order. Model parallel calls, retries, aborts, missing results, context compaction, and unknown episode boundaries. | Adversarial fixtures for cross-trace sessions, parallel calls, duplicate history, delayed scores, orphaned tools, and incomplete captures produce deterministic graphs or explicit `unknown`/rejection reasons. No future result appears in an earlier decision's visible prefix. |
| **v0.3.0 — robust capture boundary** | Evolve `CaptureWriter` into a documented instrumentation API with explicit `begin`, `finish`, `abort`, and delivered-result records; provider-native payloads remain opaque and versioned. Add safe concurrent writing or per-run files with deterministic merging, crash recovery, and bounded/redacted report output. | Concurrent and interrupted writes cannot be mistaken for a completed decision. Missing tool schema is distinct from an explicitly empty schema. Actual delivered content and backend raw content have separate provenance. No automatic network transmission of the private sidecar. |
| **v0.4.0 — read-only Langfuse pull** | Add an explicit, bounded `pull` command using v2 observations and v3 scores. Support project/base URL selection, field groups, pagination, dry-run scope preview, rate-limit retry, checkpoint/resume, and trace-scoped consistency checks. Record an explicit completeness state and collection watermark; do not infer completeness from a final cursor alone. Credentials stay in the environment or a user-selected secret store. | Synthetic paginated API tests and local self-hosted integration tests agree with offline import; interrupted pulls resume without lost or duplicate rows in the tested window. Delayed score reconciliation creates a new snapshot/revision and never mutates the original evidence. No model call or Langfuse write is required. |
| **v0.5.0 — bulk intake and bounded resources** | Read complete enriched blob manifests and observation/score files, starting with JSONL and adding Parquet through an optional extra. Stream normalization and report generation; keep hash and provenance checks. | A representative 100,000-observation fixture completes with a documented peak-memory target of **under 1 GiB**, and interrupted processing resumes to the same normalized output hashes. Incomplete manifests, unsupported schema variants, and changed source rows fail visibly. If the resource target proves inappropriate, revise it publicly before the release candidate. |
| **v0.6.0 — dataset eligibility and exports** | Stabilize structural, quality-signal, rights, privacy, and split checks as separate gates. Require component-level use attestations and an explicit quality-selection policy for training export. Emit versioned generic episodes and a Chat SFT view only for validated Chat captures; retain other provider formats without lossy conversion. Provide a dataset manifest with selection counts, rejected reasons, source hashes, transform version, and trace/task split evidence. | Re-running on the same snapshot yields byte-identical rows and report. Missing permission, exact prefix, tool schema, delivered result, or split provenance blocks the corresponding training export. A score alone does not imply correctness; scores and gold labels never enter historical model input. Redaction is explicit and its limits are documented. |
| **v0.9.0 — release candidate** | Freeze the v1 schema and public Python/CLI contracts; publish JSON Schemas, migration notes, compatibility matrix, threat model, end-to-end guide, and failure examples. Test clean installation on the declared Python versions and supported Langfuse server/API versions. Compare the same difficult fixtures with plain Langfuse export and at least one existing preparation tool. | No known P0 error that silently marks incomplete data eligible, leaks private content, loses data on resume, or breaks documented inputs. Offline, API, and blob paths pass the same conformance suite. Users can audit a report back to original source IDs and hashes. |
| **v1.0.0 — stable release** | Tag the GitHub release and publish the package after the candidate gates pass. Guarantee SemVer for documented APIs and a schema migration path for v1 archives; document support and deprecation policy. | A new user can collect or import Langfuse data, inspect eligibility, and export only permitted views without reading this project's research notes or running a model. Release artifacts are reproducible and contain only intended public files. |

Milestones are gates, not calendar dates. A preview may ship with explicit limitations; v1.0.0 waits for the reliability and contract gates. Features can move between pre-1.0 versions, but the exit gates for provenance, completeness, privacy, and reproducibility must remain.

## Current state and next implementation slices

The v0.1.0 source preview has a synthetic quickstart, release checklist, lint and unit checks, build checks, and an initial commit. A package release has not been made.

1. **Episode schema and fixtures:** define canonical event JSON Schema and state transitions; add pathological synthetic snapshots before writing a broad stitcher. Keep `candidate` (structural) separate from `quality` and `rights` in both report and API names.
2. **Collector specification:** write a bounded v2/v3 pull contract with cursor, idempotency key, incomplete-page recovery, delayed-score revision, and credential handling, then implement the smallest read-only vertical slice.
3. **Capture hardening:** make begin/finish/abort and delivered-result boundaries explicit, then test interrupted and concurrent writes before treating them as complete decisions.

## v1 release rules

- Source data, captures, and exports are local and private by default. The CLI must not print prompts, tool results, credentials, or raw provider payloads in normal reports.
- Every transformation records source IDs, source hashes, schema/adapter versions, filtering rules, and exact exclusions. A declared `complete` flag without verifiable collection evidence is not treated as proof of a complete episode.
- `faithful` means only that required capture relationships were observed. `eligible_for_<view>` additionally checks that view's format and declared use. Answer correctness is a separate label.
- An unknown or ambiguous relation fails closed for a faithful training view while remaining available for diagnosis.
- Provider/model terms and third-party corpus rights are supplied and reviewed by the user of Trailgate. The library can enforce a declaration; it cannot certify legal permission.
